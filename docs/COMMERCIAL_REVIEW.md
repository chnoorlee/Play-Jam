# 《余信》试玩版本商业评审与改进记录

评审日期：2026-11-22。本记录是开发代理基于代码、试玩流程与官方案例做出的内部设计评审，不是发行商意见、赛事评分或真实玩家研究。没有取得销量、付费转化、留存或盈利数据。本文将改动前的问题、当前改动及验证状态分别记录；开发完成不等于体验改善已被玩家证实。

## 本轮结论

现有版本已经具备可描述的叙事核心：在即将被潮水淹没的邮站，通过两个时态把三封迟到的信送到人手中。改动前最影响后续商业验证的问题，是机关主要依赖照抄答案，完成投递的情绪反馈较短，探索顺序与目标提示不一致，以及画面、可读性和存档迁移缺少可调节手段。

本轮已经实现三种不同机关、回执与纪念物，并补足提示、显示、声音、存档和结局导出控制；本地构建、32 项单元测试和 25 项浏览器记录均通过。它是进一步接近商业体验的 Demo，仍需真实玩家盲测与内容体量扩充。尚无证据支持正式付费发行、预计售价、销量预测或“AI 制作已获商业成功”的判断。

## 改动前的问题与本轮对应

以下“改动前”指本轮升级前的代码与已交付 Demo，不是对全体玩家体验的统计结论。

| 优先级 | 可复核的问题 | 可能影响 | 本轮改动与验收方式 |
| --- | --- | --- | --- |
| 高 | 钟楼三个铜环独立递增，家书直接给出 III / I / II；温室也是把三个方向逐个调到手记答案 | 两个机关操作结构接近，推理变化不足 | 钟轮改为单向联动；温室展示连续光路。检验玩家是否能解释规则、定位错误，以及是否把它们当成两种谜题 |
| 高 | 站台只需在两个时态收集邮戳，随后直接出现人物选择 | 切换时态有门槛，但邮戳内容对推理作用较小 | 收齐后重组“北站、停运、南岸、重逢”的有序地址；错误可以重新排列，不损失物品 |
| 高 | 投递后主要是简短反馈与手记摘要 | 选择虽被记录，收件人接住信以后的生活缺少可收藏的反馈 | 六种人物选择各有回执正文与纪念物；按实际投递顺序收集，结局可回看。检验玩家能否把回执与自己的选择对应 |
| 中 | 守灯人说投递顺序不限，目标文字却优先指向钟楼、再温室、最后站台 | 主动探索另一条路线时，当前目标可能与玩家正在做的事不一致 | 目标跟随最近接触的任务；未选任务时给出仍可探索的位置。检验三条起始路线均能继续 |
| 中 | 线索与失败文本存在，但没有按需分层提示 | 自行理解与直接看攻略之间缺少过渡 | 每个机关提供三层提示：关注位置、解释规则、具体操作；按需查看，记录求助层级 |
| 中 | 默认镜头、文字与动态表现缺少玩家可调选项 | 小屏辨识、阅读舒适度与不同设备负担尚缺少调节方式 | 增加镜头放大、画质、音量、大字体、减弱动态设置；需逐项验证即时效果、保存与布局 |
| 中 | 进度只留在当前浏览器的本地存储 | 更换浏览器、清理数据或备份时缺少可携带存档 | 增加 JSON 备份与恢复；验收导出、导入、错误文件提示和恢复后可继续通关 |

## 真实玩家测试方案

这是尚未执行的计划，人数和门槛均为项目内部拟定值，不是已取得的数据或赛事标准。

1. **先冻结可测试版本。** 记录提交版本、线上地址、测试日期与设备；先通过全部规则测试及正式构建的完整浏览器流程，确认三个结局、保存恢复、全部设置和错误恢复可操作。
2. **首轮招募 6–8 位目标玩家。** 以偏好叙事冒险或轻解谜的玩家为主，纳入不熟悉本作的玩家；混合桌面与手机用户。开始前取得记录同意，不把开发代理或熟悉答案的人算作首次玩家。
3. **不提示答案进行试玩。** 只给出游戏入口，请玩家按自己的方式完成；允许使用游戏内提示。记录首个有效互动、第一次切换时态、机关尝试与失败、查看提示层级、迷路或求助、退出和完成位置。玩家请求帮助时记录帮助内容与原因。
4. **在结局后询问理解与感受。** 让玩家用自己的话复述三位收件人的处境、一次机关规则、一次选择及后果；询问最想保留的回执或纪念物、最困惑之处、是否愿继续游玩以及理由。不用带有答案的选项诱导肯定评价。
5. **把问题回到录像和操作证据。** 将卡点分为规则理解、寻找目标、点击操作、阅读、性能或叙事困惑；保留未完成和负面反馈，不只整理称赞。小样本用于发现问题，不推算市场转化率。
6. **修订后进行第二轮。** 优先解决阻断、错误理解和反复求助，再邀请未参与首轮的玩家；保留上一轮问题及本轮是否复现。只有实际观察支持主要循环成立，才讨论扩展章节和付费范围。

拟定的继续制作条件是：大多数首轮玩家无需作者给出谜底就能完成主要循环；能指出至少一次操作如何改变人物处境；主要阻断在修订后不再反复出现。是否“愿意购买”只作为原因访谈，不当成真实购买或收入。若玩家主要称赞画面，却无法解释投递与选择，优先修复叙事和玩法联系。

## 赛事与 AI 使用说明

用户提供的海报要求原创、叙事丰富、可玩的 Demo，并提到入选后发布主题。**正式主题尚未提供，仍待主办方确认。** 海报日期存在差异；团队资格、准确期限、提交格式与 AI 披露要求同样待确认。本轮没有代为报名、提交比赛、支付费用或发布付费商店产品。
