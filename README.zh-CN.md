# 余信 / THE LAST POST

一款可直接游玩的原创 2.5D 叙事解谜 Demo。潮水即将淹没白沙邮局，邮差许渡带着三封迟到的信，在“此刻”与“回声”之间寻找收件人。投递的答案，未必等于告别的答案。

## 启动

在线版：[https://chnoorlee.github.io/Play-Jam/](https://chnoorlee.github.io/Play-Jam/)。玩家直接打开链接即可游玩，无需安装 Node.js。使用支持 WebGL 的现代浏览器，建议开启硬件加速。

本文包含 2026-11-22 的本轮升级说明。本地验证见 [验证记录](docs/VERIFICATION.zh-CN.md)；线上发布状态以对应提交的 [GitHub Actions 结果](https://github.com/chnoorlee/Play-Jam/actions/workflows/deploy.yml) 与在线检查为准。

从 GitHub 克隆的源码不包含构建产物，需要先安装 Node.js 22.12+ 并在项目目录运行：

```powershell
npm ci
npm run build
```

构建后，或使用已包含 `dist/` 的完整游戏包时，Windows 双击 `start.cmd`，浏览器会自动打开。游玩时保留启动窗口；关闭窗口即可停止本地服务。运行已构建的 `dist` 需要 Node.js 22.12+，不需要安装 npm 依赖。

也可以在本目录运行：

```powershell
node server.mjs
```

访问终端显示的本机地址，默认 `http://127.0.0.1:4173`。端口占用时会自动选择其他空闲端口。不要直接双击 `dist/index.html`，模块需要通过本地 HTTP 服务打开。

## 游玩

- 点击场景或地标自动行走；点击地标会走近并交互。触屏可直接点按。
- `WASD` / 方向键移动，`E` 与近处目标互动。
- `Q` 切换“此刻 / 回声”，`J` 查看投递手记，`Esc` 暂停或收起窗口。
- 右上角可开关音乐；默认静音。文字线索不依赖声音。
- 场景旁的放大、缩小和全景图标调整镜头；放大时镜头跟随角色，全景可恢复整体构图。
- 三封信可任意顺序投递。钟楼需要理解铜环联动，温室需要接通连续光路，站台需要跨时态收集并重组邮戳。每次机关完成后还需作出人物选择，才算送达。
- 投递手记包含“信笺”“投递”“回信”分类，可重读线索、查看剩余地址，收集三份回执与纪念物。
- 机关或投递页的灯泡图标可打开三层提示。按需展开“再展开一张”，不会扣除物品或自动完成机关。
- 三封信全部送达后可选择三个不同结局；结局页可导出文本和 PNG 明信片，并重选最后的决定。

首次游玩建议自行探索；需要演示时可参考 [含剧透流程](docs/WALKTHROUGH.zh-CN.md)。

任一结局页的“出发 · 南岸邮路”会打开三张新的水粉风全景地图。在芦苇渡口查验潮位，在盐田配平盐秤，再去青岬气象台发送灯号。可以回访已经解锁的地点。后日谈的线索、机关进度和投递决定随浏览器存档与 JSON 备份一同保存。已有结局存档可从标题页继续。

## 显示与声音

右上角设置图标打开“灯下的片刻”。“画面”可选“流畅”或“精细”；还可调节音量、启用“大号文字”和“减弱动态”。设置会保存在当前浏览器，刷新后继续使用。音量与声音开关分别控制音量大小及是否播放；文字与机关线索不依赖音效。

“流畅”用于减少绘制负担，不是任何设备均能流畅的保证；真实电脑和手机的性能仍待实测。新设置已有 Chromium 自动化检查，尚未构成完整可访问性审计。

## 存档与导出

进度自动保存在当前浏览器、当前地址；换浏览器或端口不会自动共享存档。旧版已完成投递会保留，已验证规则层面的旧存档迁移；真实用户旧浏览器数据仍需实际核对。

1. 在设置中选择“备份投递记录”，下载 `余信-投递记录.json`。接过邮包、开始旅程以后才能备份。
2. 在需要恢复的页面打开设置，选择“恢复投递记录”，选中此前导出的 JSON 文件。
3. 查看章节与已送达数量预览，再选择“恢复这段旅程”。预览不会替换当前进度；确认后会替换本浏览器里的投递记录。JSON 只备份旅程，显示和声音设置不包含在文件中。

这是本地文件备份，不是云同步。清理浏览器数据前应先备份；如浏览器拒绝自动保存，游戏会提示。无法识别的文件会提示错误，不应当作可恢复进度。

结局页“留下这封信”下载包含结局、人物回响、回执、纪念物及 AI 辅助披露的 `余信-投递手记.txt`；“收藏夜航明信片”下载包含当前结局与三个人物回响的 `余信-夜航明信片.png`。“回到最后一夜”保留三封信的决定，供重新选择最终结局。要重选三个人物的决定，在暂停菜单中确认重新开始；这会清空本次投递进度。

## 开发

使用 Three.js 正交 3D 场景呈现 2.5D 视觉；PathFinding.js 提供 A* 寻路；Lucide 提供界面图标。程序化几何与 Web Audio 合成音频均随代码生成，运行时没有在线生成服务、外部字体或素材请求。

```powershell
npm ci
npm run build
npm test
npm run dev
```

开发服务器启动后，另开终端运行 `npm run test:e2e`。若 Playwright 尚未安装 Chromium，先运行 `npx playwright install chromium`。端到端测试默认访问 `http://127.0.0.1:5173`，可用环境变量 `GAME_URL` 指定开发地址。测试桥接只存在于开发构建，正式构建不暴露故事状态。

例如开发服务因端口占用改用 5181，在另一 PowerShell 终端运行：

```powershell
$env:GAME_URL = 'http://127.0.0.1:5181'
npm run test:e2e
```

本地构建与 44 项规则和服务器测试通过。浏览器走完了主线三个结局，并在桌面和手机尺寸下从旧结局存档续玩南岸三站。覆盖范围和真机测试情况见[验证记录](docs/VERIFICATION.zh-CN.md)。

源码：`src/world.js` 场景与寻路；`src/story.js` 剧情与存档；`src/main.js` 交互；`src/audio.js` 合成声音；`src/style.css` 界面。修改后重新执行 `npm run build`，再用 `start.cmd` 运行新版本。

## 在线发布与更新

网站通过 [GitHub Actions](https://github.com/chnoorlee/Play-Jam/actions/workflows/deploy.yml) 自动部署至 GitHub Pages。以后开发完成并把提交推送到 `main`，工作流会自动构建、运行单元与服务器测试、检查正式版浏览器渲染及基本交互，通过后更新在线版。失败时不会发布，线上保留上次成功版本；可以在 Actions 页面查看日志或手动运行工作流。

游玩地址保持不变，部署成功后刷新页面才能加载已发布版本。本地修改需要提交并推送后才会发布；具体提交是否上线以对应工作流和在线检查为准。网站没有在线账号，存档属于当前浏览器及网站地址，本地版本与在线版不自动共享存档，可用 JSON 备份迁移旅程。
